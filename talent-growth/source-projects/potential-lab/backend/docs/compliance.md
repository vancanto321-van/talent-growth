# 国内上线合规清单

> 开发阶段（mock AI + 本地后端 + 微信开发者工具预览）**不需要**任何一项。
> 正式对外发布前逐项落实。每一项都写明了办理入口或前置条件。

## 1. 主体与账号

- [ ] **小程序主体**：建议注册**个体工商户或企业**主体。个人主体的类目受限（职业规划、教育、AI 问答类目基本走不通），且无法开通微信支付。
- [ ] **类目选择**：核心类目（如"教育-职业教育"或"商务咨询"）+ 必申请 **「深度合成-AI 问答」** 类目（因为产品含 AI 生成内容）。

## 2. 服务器与备案

- [ ] 国内云服务器（阿里云/腾讯云等）。
- [ ] 域名 **ICP 备案**（云服务商控制台即可提交，约 1-3 周）。
- [ ] HTTPS 证书（备案后免费申请），`VITE_API_BASE` 切换为正式域名。
- [ ] 数据库切换 PostgreSQL（`DATABASE_URL`），并开启定期备份。

## 3. 生成式 AI 合规（重点）

依据《生成式人工智能服务管理暂行办法》与微信平台规则：

- [ ] **使用已备案的大模型**：智谱 GLM、DeepSeek、通义、豆包等均已完成网信办算法/大模型备案（保留备案号，产品内需公示模型名称与备案号）。
- [ ] **大模型登记**：自己不造模型、通过 API 提供服务的，向**省级网信办**做"大模型登记"（相对备案简单很多）。
- [ ] **微信深度合成类目资质**：需提供小程序主体与模型技术方的**合作协议**，且协议中的模型名称必须与对方算法备案名称**逐字一致**（不一致是最常见驳回原因）。
- [x] 《人工智能生成合成内容标识办法》（2025-09-01 施行，GB 45438-2025）：
  - [x] AI 生成内容加**显式标识**（界面上"由 AI 生成"提示；前端 `components/ai-badge` 徽标已挂到全部 AI 产出区块，mock 适配器显示"模拟生成（演示数据）"；评估响应透出 `ai_model` 供徽标展示模型名）；
  - [x] 导出/复制内容时带**隐式标识**（`/api/me/export` 携带 `ai_content_disclosure` 元数据：法规依据、AI 字段清单、产出模型列表）。

## 4. 内容安全

- [ ] 服务端接入微信 **msgSecCheck**（文本）/**mediaCheckAsync**（图片）：**用户输入和 AI 输出双向检测**。
  代码已预留：`backend/app/services/safety.py` 配置 `WX_APPID/WX_SECRET` 后自动启用。
- [ ] 高风险场景建议叠加腾讯云天御/内容安全专业版。
- [ ] 建立违规内容处置与投诉举报通道（小程序管理后台可配）。

## 5. 个人信息保护（PIPL）

- [ ] 《隐私政策》+ 首次运行弹窗同意；小程序后台填写"用户隐私保护指引"。
- [ ] 最小化收集：目前只收集昵称（可选项）、年龄段（可选项）、用户主动输入内容。
- [ ] 探测访谈涉及个人经历，属敏感数据：数据加密存储/传输（HTTPS + 数据库层面）、提供删除账号与数据的功能。
- [ ] **未成年人保护**：年龄段若含未成年，需要监护人同意机制 + 内容适配；这是"各年龄段用户"定位下的硬要求。

## 6. 产品话术红线（同时是科学诚实问题）

- [ ] 不承诺"测出先天天赋/天赋分数"——产品实现为"线索 → 验证 → 培养"，页面文案已内置诚实声明（`profile.py` 的 HONESTY_NOTE）。
- [ ] 不使用"超过 95% 的人"类人群比较（无参照人群数据）。
- [ ] 不把进步归因于先天因素。
- [ ] AI 评估必须展示依据（已实现：evidence_quotes 引用用户原话）。

## 6b. 儿童版专项合规（新增）

**量表与宣传授权：**
- [ ] 八个观察维度**参照哈佛大学加德纳教授多元智能理论自编中文题**。加德纳官网明确"不存在加德纳认证的 MI 测评"——**严禁宣传为"哈佛量表/哈佛认证"**，页面声明已内置（`services/child_assessment.py` 的 DECLARATION）。
- [ ] "毅力（grit）"“思维模式（growth mindset）"的**原量表（宾大 Duckworth / 斯坦福 Dweck）仅限非商用**；产品内为按公开维度自行改写的中文题。若未来需要原题商用，须联系权利方获得授权。
- [ ] 不可复用的知名儿童量表（均勿模仿其题目）：WISC 等智力测验（商业授权+测量师资质）、哈佛零点项目 Project Spectrum（研究工具）、VIA-Youth（题目专有）、CBCL/Conners（商业）。
- [ ] **不得宣称"测出孩子的天赋/智力"**：儿童报告输出"类型=当下行为倾向"，会变化、可重测；不能替代专业机构评估（声明已内置）。

**未成年人个人信息（PIPL）：**
- [ ] 不满 14 周岁未成年人信息属**敏感个人信息**：需要**监护人单独同意**（付费操作须由监护人完成，页面已加提示；正式上线需增加监护人身份确认环节）。
- [ ] 最小化收集：目前仅收集小名/称呼、年龄段、家长代答的问卷答案——不收集学校、照片、住址。
- [ ] 提供删除儿童数据的功能；微信端配合"未成年人个人信息保护"指引与青少年模式。

**支付相关：**
- [x] 付费主体必须是监护人；¥5/次、¥29/月 的定价在 `backend/app/config.py`（分）配置。
- [x] 未成年人大额消费风险："单日/单月付费上限"与消费提醒已实现（`config.minor_daily/monthly_pay_limit_cents` 默认 ¥50/日、¥100/月，下单与支付双重拦截，测试 `tests/test_compliance.py`；付费页已加监护人确认与限额提示文案）。

## 6c. 微信支付上线步骤（当前为模拟支付）

代码已留好全部接口（`services/billing.py` 模块注释），上线时：
1. [ ] 企业主体 + 微信支付商户号（mch_id）+ API 证书，在商户平台开通 JSAPI 支付。
2. [ ] 后端 `create_order` 里调用微信"统一下单"（`/v3/pay/transactions/jsapi`），用返回的 `prepay_id` 组装 `payParams`（timeStamp/nonceStr/package/signType/paySign）返回给前端。
3. [ ] 前端解锁按钮改为 `uni.requestPayment({ provider: 'wxpay', ...payParams })`。
4. [ ] 新增 `POST /api/billing/wechat-notify` 回调接口：验签 → 订单置 `paid` → 返回成功应答。**订单状态只能以回调为准**。
5. [ ] `.env` 设置 `ALLOW_MOCK_PAY=false`（mock-pay 接口将直接拒绝）。
6. [ ] 对账：每日拉取微信账单核对订单。

## 7. 微信平台技术要求

- [ ] `request` 合法域名：正式版必须为备案 HTTPS 域名（开发工具勾选"不校验合法域名"仅限开发）。
- [ ] 正式登录：`wx.login` code → 后端 `/api/auth/wx-login`（已实现，签发 HMAC 签名会话，30 天有效，支持登出撤销）。
- [ ] 上线环境变量：`ALLOW_MOCK_AUTH=false`（关闭明文令牌与 mock-login）、`ALLOW_MOCK_PAY=false`（关闭模拟支付）、`SECRET_KEY=强随机值`（更换即全员重新登录）。
